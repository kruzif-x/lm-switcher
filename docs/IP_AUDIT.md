# IP / Copyright Audit — LLM Switcher

Date: 2026-07-11 · Scope: full repo at branch `worktree-mcp-spec` · Purpose:
pre-Mac-App-Store clearance.

## Method

- Scanned all source (`src/`, `scripts/`) for license headers, SPDX tags,
  attribution comments, and source-URL markers.
- Fingerprint search for code from the two third-party projects reviewed
  during design (vorssaint-utils GPL-3.0, oMLX Apache-2.0): distinctive
  symbol names (`host_statistics64`, `vm_statistics64`, `memorystatus`,
  `xsw_usage`, `IOPSCopy*`, `MetricFormat`, `mach_port_deallocate`, engine
  pool identifiers).
- Enumerated every SF Symbol used (direct and via helper parameters).
- Reviewed linked frameworks, build-time fetches, bundled assets, and
  brand-name usage in UI text.

## Findings

### Clean

| Area | Result |
|------|--------|
| Third-party code in repo | **None.** All Swift/bash/Python sources are original to this project. No vendored dirs, no build-time fetches (`install.sh` compiles local sources only) |
| vorssaint-utils (GPL-3.0) fingerprints | **Absent.** The three memory techniques exist only as spec text (own words, own formulas); implementation is mandated clean-room (MCP_SPEC §3.6). Kernel API names and sysctl keys are unprotectable facts |
| oMLX (Apache-2.0) | **No code copied.** Only REST endpoint facts referenced in the spec; API designs adapted as ideas (not copyrightable). If code is ever copied later, Apache-2.0 attribution applies — current policy is: don't copy |

| App icon | Original, generated by `make_icon.py` in-repo (own geometry, own gradient) |
| Screenshots / README art | Own screenshots; Mermaid diagram is authored markup |
| Help/About/README prose | Original. Gemma/Qwen/GLM/llama.cpp mentions are nominative (describing compatibility) — standard fair use |

### Recommendations before App Store submission (not infringement, but adjacent)

1. **CLI name `llama`** — Meta holds trademarks around "Llama" for AI. As a
   local command name it's low-risk, but if the CLI ships inside the MAS
   product, rename it (e.g. `llmsw`) to keep the product surface clean.
2. **Repo license vs paid app** — the repo's public "free to use, no
   reselling" license means anyone may build and use the app for free. That
   is a business-model conflict with a paid MAS listing (not a legal one —
   you own the code and can dual-license). Decide: keep repo public as the
   free tier, or take it private before launch.
3. **SF Symbols going forward** — when adding symbols, avoid the restricted
   list (any Apple product/brand glyphs: `apple.logo`, `airpods*`,
   `applewatch*`, `macbook*`, etc. used decoratively). All other symbols
   currently used are unrestricted.
4. **MAS compliance checklist** (separate from copyright): App Sandbox
   re-architecture (spawning external binaries, `ps` scanning, `~/bin`,
   LaunchAgent are all sandbox-incompatible — see MCP_SPEC §9 note), and
   `ITSAppUsesNonExemptEncryption = false` in Info.plist (no non-exempt
   crypto; CryptoKit is used for hashing only).

## Standing policy (recorded for future sessions)

- Third-party **code** is never copied into this repo, regardless of
  license. Techniques are re-implemented clean-room; public API names,
  sysctl keys, formulas, and protocol facts are usable freely.
- Any future exception requires: license permits proprietary use (MIT/BSD/
  Apache), attribution file added, and a note in this document.

## Verdict

**No infringing code in the repository.** One Apple-symbol licensing issue
found and fixed. The planned Phase 1/2 implementations are specified
clean-room and introduce no third-party code. Items 1–2 above are business
decisions to make before the MAS listing; item 4 is a separate technical
prerequisite for MAS regardless of IP.
